## 1. 불변식 (Invariants) — 어떤 기능·리팩터링·핫픽스도 이걸 깨면 안 된다

| # | 불변식 | 왜 (근거) | 코드에서의 강제 지점 |
|---|---|---|---|
| I1 | **본인인증 + 크루 초대 없이는 어떤 경로로도 아이 인계가 일어날 수 없다** | 신뢰 관문 2단 (§19-4). 안전의 최소선 | 세션 생성·참여 로직의 전제 조건. 우회 API 금지 |
| I2 | **포괄 합의(책임범위·알레르기·비상연락·사진 동의·만14세 미만 법정대리인 동의) 없이는 크루 활동을 시작할 수 없다** | Q7 면책 전략의 성립 조건 + 개인정보법 (§19-5) | 크루 가입 플로우 필수 단계. 아이 프로필 변경 시 재동의 |
| I3 | **무인가 보육 패턴 금지 (이웃 트랙 한정)**: 돌봄자 1인 + (자기 아이 제외) 영유아 5인 이상 세션은 생성 불가. 상시화 패턴은 경고 | 영유아보육법 "상시 5인" (§18). 시터 트랙 정기 돌봄은 자격·등록 통로로 별도 처리 | 세션 생성 검증. 하드 블록 + 패턴 감시 |
| I4 | **고르기는 사람**: 배정 확정·시터 선택은 반드시 복수 후보 중 각 가정의 명시적 확정 탭. 앱은 후보 나열·계산·독촉만 자동화한다 | 자동화-책임 역설 (§15-R10, §19-6). "앱이 골랐다"를 성립 불가능하게 | 배정·매칭 UI/API. 단일 자동 확정 금지 |
| I5 | **이웃 트랙의 돈은 앱이 영구히 만지지 않는다**: 크레딧은 비화폐·환급 불가, 정산은 계산+독촉+딥링크까지만 | 전자금융·직업안정법·관계 보호 (§8, §19-1). 시터 트랙 결제는 수익화 시점에 별도 도입 — 이 불변식과 무관 | 크레딧·정산 모듈. 환급·이체 실행 코드 자체를 만들지 않음 |
| I6 | **크루 데이터는 크루 밖으로 나가지 않는다**: 사진·장부·아이 정보·규약 전부 크루 멤버 한정. 사진은 외부 공유 기능 자체가 없음 + 반출 금지 고지 | 타인 아이 초상권 (§19-7) + 크루=신뢰 경계 (§6) | 모든 조회 API에 크루 멤버십 검증. 공유 URL·크로스 크루 조회 금지 |
| I7 | **규약 없는 크루는 활성화되지 않는다**: 필수 항목(단가·정산모드·호스트 사례·벌금·육아 규칙·인계 방식) 합의 완료 전엔 세션 생성 불가. 앱이 기본값을 제시하고 크루는 조정만 (백지 협상 금지) | 사전 합의 = 검증된 성공 요인 (§6, §16). 백지 협상 = 민망한 대화 (§9) | 크루 생성 플로우. 규약 미완성 상태의 세션 생성 차단 |
| I8 | **연령 분기 금지**: 연령 제한·연령별 기능 분기를 만들지 않는다 (예외: 0~2세 보류 플래그, I3의 영유아 카운트) | 연령 선별은 크루의 자기조직화가 수행 (§13) | 도메인 모델에 연령 조건 로직 추가 시 리뷰 필수 |

## 2. 범위 밖 (Out of Scope) — 요청이 와도 만들지 않는다 (변경은 결정 대장 갱신 후에만)

- **자유 채팅/메신저** — 카톡과 경쟁하지 않는다. 구조화된 입력(보드·규약·확인 탭)만 (§7, §11)
- **동네 발견/커뮤니티 레이어** — 크루 밀도 확보 후 후행 (§6). MVP엔 없음
- **병상보육(아픈 아이 당일 돌봄)** — 명시적 범위 밖 (§15-R7)
- **크레딧 현금 환급 / 앱 내 크레딧 구매** — I5 위반 (§8)
- **GPS 실시간 추적** — 위치는 행정동 단위까지만 (시장조사 §4)
- **0~2세 영아 세션** — 별도 안전 판단 전까지 보류 (§13 플래그). 해제하려면 법률 확인 + 별도 합의 절차 설계 선행
- **광고** — 최후순위, 현 단계 고려 안 함 (§20)

## 3. 법률 확인 게이트 — 아래는 변호사 확인 전 "정식 출시 불가" 항목 (개발은 가능)

1. 약관 면책의 실제 효력 범위
2. "상시" 판단 기준 (빈도·기간·대가성) — I3의 세부
3. 시터 정기 고용 시 근로관계 성립 여부 + 민간 아이돌봄기관 등록제 활용 요건
4. 만 14세 미만 아동 정보·사진 동의 절차의 적법성 (I2 구현 검토)
5. **감사 기록 보존 vs 삭제권**: 탈퇴·삭제 요청 시에도 인계·합의 기록을 분쟁 대비로 보존할 수 있는 범위 (개인정보법 충돌 검토)

## 4. 데이터 원칙

- 아이 정보는 최소 수집 (이름/생년월·성향·알레르기·투약·비상연락 — 그 이상 금지)
- 사진 기본 비공개, 크루 한정 (I6)
- 위치는 행정동 단위 초과 수집 금지
- 크레딧·정산·인계 기록은 감사 추적 가능해야 함 (수정 시 이력 보존, 삭제 대신 무효화)

## 4-A. 실패 전략 — 나쁜 일이 일어났을 때 시스템의 동작

| 실패 | 시스템 동작 원칙 |
|---|---|
| 노쇼·급취소 | 규약의 벌금 규칙대로 앱이 고지 (사람이 악역 되지 않게). 반복 시 크루에 배지로 가시화 |
| 인계 확인 누락 | 세션은 "미확인" 상태로 남고 리마인드. **누락을 소급 조작할 수 없다** (기록 무결성 > 깔끔한 데이터) |
| 세션 중 사고 | 앱의 역할 = 기록 제공: 합의서·인계 시각·세션 사진·비상연락 타임라인을 즉시 열람 가능하게. 판단·중재는 하지 않는다 |
| 정산 미이행 | 독촉 자동화 + 미정산 배지 공개(투명성이 강제력). 앱이 회수를 대행하지 않음 (I5) |
| 시터 노쇼 (공구) | 크루 전체에 즉시 알림 + 크루 재요청 폴백 재가동. 환불·배상은 시터 트랙 규정으로 (수익화 시점에 설계) |
| 분쟁·탈퇴 | 크루 데이터는 남은 멤버에 보존, 탈퇴자 기록은 익명화하되 인계·합의 기록은 법률 게이트 5 결론까지 보존 |

## 5. 개발 방식 (하네스 룰)

- **문서가 소스 오브 트루스**: 제품 결정은 [00-ideation.md](00-ideation.md) §17(결정 대장)+§19(재감사)가 최신. 충돌 시 §19 > §17 > 본문
- 새 결정·번복은 **코드보다 결정 대장 갱신이 먼저**
- MVP 정의: 주간 보드 파이프라인 한 바퀴 (가능시간→배정→빈칸→폴백→세션→사진→장부→정산) (§12)
- 스택: 미정 — 결정 시 이 문서에 추가
- **모든 불변식(I1~I8)은 자동 테스트로 강제한다** — 기능 구현 시 해당 불변식의 위반 시도 테스트를 함께 작성. 문서에만 있는 불변식은 죽은 불변식이다
- 불변식과 충돌하는 요청을 받으면: 구현하지 말고 충돌을 보고할 것
