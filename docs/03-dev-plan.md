## 스택 (확정)

| 층 | 선택 | 근거 |
|---|---|---|
| 앱 (iOS+Android) | **React Native (Expo) + TypeScript** | 크루는 그룹 제품 — 한 명만 안드로이드여도 크루 전체 불가 → 양 플랫폼 첫날부터 필수. 사용자 React 경험 보유. Swift 계정·경험은 배포/네이티브 모듈에서 활용 |
| 웹 현관 | Expo Web (초대 랜딩·읽기 전용 뷰만) | "웹은 현관, 앱은 집" — 카톡 링크 첫 30초용. 풀 기능 웹 없음 |
| 백엔드 | **Python FastAPI** | 사용자 주력 언어. 1인+하네스 반복 루프 속도 우선. OpenAPI→TS 타입 자동 생성으로 타입 공유 회수 |
| 인프라 | **Supabase** (관리형 Postgres + Auth + Storage) | 인증·사진 스토리지 직접 구축 회피 |
| 푸시 | Expo Push | 총무의 생명 = 푸시 (독촉·사진·보드 리마인드) |

### 경계 룰 (아키텍처 불변식)
- **모든 도메인 규칙(I1~I8)은 FastAPI에만 산다.** Supabase는 인프라로만 사용
- **앱은 Supabase에 직접 쓰지 않는다** — 모든 쓰기는 FastAPI 경유. (읽기도 원칙적으로 API 경유, 사진 다운로드 등 서명 URL 예외만)
- Supabase RLS는 심층 방어(2차 방어선)로만 — 규칙의 원본이 아님

## 단계 (MVP = 파이프라인 한 바퀴) — P0~P5 완료 (2026-08-28), P6은 MVP 검토 후

검토 대기 메모: 보드 배정이 인접 슬롯을 병합하지 않음(1시간 슬롯 여러 개 ≠ 연속 가능 시간) — 검토 라운드에서 다룰 것.

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| ✅ P0 | 리포 구조(모노리포: app/ + api/), CI, 스캐폴드, Supabase 프로젝트 | 앱 빈 화면 + API 헬스체크 + 불변식 테스트 하네스 골격 |
| ✅ P1 | **도메인 코어**: 계정·크루·초대·규약(기본값 제시)·아이 프로필·포괄 합의 | I1·I2·I6·I7·I8 테스트 통과. UI 없이 API만 |
| ✅ P2 | **주간 보드**: 가능시간 입력→배정 후보 산출→각 가정 확정→세션 생성. 빈칸 감지 | I3·I4 테스트 통과 |
| ✅ P3 | **앱 MVP 화면**: 온보딩(초대 수락)→크루·규약→보드→세션(인계 탭·사진) | 실기기에서 크루 1개가 한 주 흐름 완주 |
| ✅ P4 | **장부·정산**: 크레딧 기록, 월말 계산, 독촉 푸시, 토스/카카오페이 딥링크, 미정산 배지 | I5 테스트 통과. 파이프라인 한 바퀴 완성 = **MVP 완료** |
| ✅ P5 | 웹 현관: 초대 랜딩 + 읽기 전용 보드 | 카톡 링크→가입 전환 흐름 동작 |
| P6 | 시터 트랙 (공구 제안·분할 견적·긴급 할증) | 후순위 — MVP 검증 후. 결제 도입은 수익화 시점 |

- 순서 원칙: **도메인·불변식 먼저, UI 나중** — 하네스가 테스트로 검증 가능한 것부터
- P1~P2는 UI 없이 진행되므로 지루해 보여도 순서 준수 (불변식이 뼈에 박혀야 이후가 빠름)
- 본인인증(PASS 등)·세션 보험은 P6 이후 외부 연동 단계에서 (MVP는 Supabase Auth 계정 수준)
