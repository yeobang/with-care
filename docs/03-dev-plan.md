## 스택 (확정)

| 층 | 선택 | 근거 |
|---|---|---|
| 앱 (iOS+Android) | **React Native (Expo) + TypeScript** | 크루는 그룹 제품 — 한 명만 안드로이드여도 크루 전체 불가 → 양 플랫폼 첫날부터 필수. 사용자 React 경험 보유 |
| 웹 현관 | Expo Web (초대 랜딩·읽기 전용 뷰만) | "웹은 현관, 앱은 집" — 카톡 링크 첫 30초용. 풀 기능 웹 없음 |
| 백엔드 | **Python FastAPI** | 사용자 주력 언어. OpenAPI→TS 타입 공유 |
| 인프라 | **Supabase** (관리형 Postgres + Auth + Storage) | 인증·사진 스토리지 직접 구축 회피 |
| 푸시 | Expo Push | 총무의 생명 = 푸시 (독촉·사진·보드 리마인드) |

### 경계 룰 (아키텍처 불변식)
- **모든 도메인 규칙(I1~I8)은 FastAPI에만 산다.** Supabase는 인프라로만 사용
- **앱은 Supabase에 직접 쓰지 않는다** — 모든 쓰기는 FastAPI 경유 (사진 서명 URL 등 읽기 예외만)
- Supabase RLS는 심층 방어(2차 방어선)로만 — 규칙의 원본이 아님

## 완료 단계 (P0~P5, 2026-08-28) — 파이프라인 한 바퀴

P0 스캐폴드·CI → P1 도메인 코어(I1·I2·I6·I7·I8) → P2 주간 보드(I3·I4) →
P3 앱 화면·세션 사진 → P4 장부·정산(I5, §21·§22) → P5 웹 현관(초대 랜딩).
이후 보강(2026-08-31): 정산 상쇄(§22)·재호출 방어·초대 TTL·재동의·RLS 실적용.

## 완제품 로드맵 (P6~P11) — §23: 검증 게이트 없이 연속 진행

원칙 유지: 각 단계는 짧게 끊고, 끝날 때마다 동작 상태(테스트 green)로 되돌린다.

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| P6 | **실인증**: Supabase Auth JWT 서버 검증 + 앱 로그인 교체, dev 헤더(X-User-Id) 게이트 해제. 본인인증(PASS 등)은 사업자 요건 확인 후 어댑터 자리에 연결 | prod 모드에서 JWT로 전 API 동작, 위조 토큰 401 테스트 |
| P7 | **푸시**: Expo Push 토큰 등록 + 발송 인프라. 독촉(미정산)·보드 마감 리마인드·배정 확정 요청·세션 사진 알림 | 실기기 수신 확인, 발송 실패가 본 흐름을 막지 않음(degrade) |
| P8 | **보드 완성**: 인접 슬롯 병합(검토 메모 해소), 빈칸 감지→크루 재요청 폴백, 배정 거절(DECLINED) 흐름 | 빈칸이 "감지→재요청→해소/미해소" 상태를 가짐 |
| P9 | **규약 집행**: 노쇼 기록·벌금 자동 고지·반복 배지(악역의 자동화), 호스트 사례(host_fee) 정산 반영, rotation 모드 균형 알림 | 실패 전략 §4-A의 노쇼 행이 실코드로 존재 |
| P10 | **시터 트랙**: 공구 제안·분할 견적·긴급 할증(당일 1.5배)·시터 노쇼→크루 폴백 재가동. 결제 포함 여부는 별도 결정(아래 열린 결정) | I3 상시성 감시가 시터 공구를 주 대상으로 동작 |
| P11 | **배포·운영**: API 호스팅, prod CORS·시크릿, EAS 빌드→스토어, 웹 현관 읽기 전용 보드, 백업·구조화 로그 | 외부인이 초대 링크로 실기기에서 한 주 완주 |

## 병행 트랙 (개발을 막지 않되 출시를 막는 것)

- **법률 게이트 5건** (guardrails §3) — 변호사 확인 전 정식 출시 불가. 코드로 해소 불가
- 인터뷰·실사용 검증 (§17-C) — §23으로 게이트에서 병행으로 재분류
- 세션 보험 제휴 (§20-3) — 수익화 시점 카드

## 확정된 결정 (2026-08-31, 사용자)

1. 앱 로그인: **이메일 OTP 먼저** — 카카오 OAuth는 개발자 앱 키 확보 시 2단계로 추가
2. 본인인증: **사업자 없음 → 어댑터만** — Supabase Auth 계정 인증까지. 본인인증은
   IdentityVerifier 어댑터(스텁)로 I1 강제 경로를 실물로 두고, PASS류는 사업자 확보 후 교체
3. P10 결제: **제외** — 공구 제안·분할 견적·확정까지. 지불은 딥링크·현장.
   PG 도입은 수익화 시점 별도 결정 (§19-1과 일치)
